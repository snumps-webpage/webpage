# 실측 하네스 — 떠 있는 서버를 실제로 두드려 본다

단위 테스트는 함수를 부른다. 이 하네스는 **실제 dev 서버를 띄우고 HTTP와 브라우저로
사용자를 흉내 낸다** — 가입 → 승인 → 세미나 신청·게시·취소·삭제, 학기 경계를 넘는
재가입, 병렬 요청 경쟁까지. 2026-09-27에 이 방식이 단위 테스트가 전부 초록일 때 놓친
결함 여럿(발표자 자동 출석이 모든 취소 세미나 삭제를 막음, `/.//host` 오픈 리디렉트,
게시·취소 ↔ 삭제 경쟁)을 잡았다.

**운영·dev Supabase를 건드리지 않는다.** 서버는 `.env` 없이 메모리 백엔드로 뜨고,
Google 값이 가짜라 메일은 한 통도 나가지 않는다.

## 구성

| 파일                     | 역할                                                                                                                                                                                                                                                                                                             |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `start.sh`               | 레포를 작업 디렉터리로 복사(비밀값·개인정보 제외) → 시드 API 주입 → `env -i`로 vite dev 기동                                                                                                                                                                                                                     |
| `clock.cjs`              | 서버의 `Date`를 오프셋 파일만큼 옮기는 preload. 재시작 없이 시간을 옮긴다(학기 경계 재현)                                                                                                                                                                                                                        |
| `inject/probe-server.ts` | **시드 API** 원본. `start.sh`가 복사본에만 `src/routes/api/__probe/+server.ts`로 넣는다                                                                                                                                                                                                                          |
| `lib.mjs`                | 공용 헬퍼 — 세션 쿠키 위조, `use:enhance` 형식 POST, 시드 API, 시계, PASS/FAIL 집계, 학기 기준 날짜. `applySeminar`는 세미나 신청을 폼과 같은 필드(정기/비정기, 소요 시간, 신청자를 발표자로)로 보낸다 — 액션이 도메인 스키마로 검증하므로 빈 `{title, description}`은 거부된다. `memberIdOf`는 이메일 → 회원 id |
| `scenarios.mjs`          | 합성 데이터 끝-끝 시나리오 (로그인 리디렉트, 재가입·`/wait`, 대시보드, 세미나 삭제, 전화번호, 전체 크롤). S10은 취소·삭제된 세미나의 신청이 발표자에게 "취소됨"으로 남는지, S11은 취소된 이벤트 404·가드 거부의 `no-store`·없어진 `/?/updateSeminar`·관리자 스터디 목록을 본다                                   |
| `race.mjs`               | 게시↔삭제, 취소↔삭제를 실제 병렬 요청으로 반복하고 불변식을 확인 (`RUNS`, 기본 10)                                                                                                                                                                                                                               |
| `real.mjs`               | 백업 스냅숏을 올려 실데이터로 전 라우트·전 회원 화면 확인 — **개인정보 주의** (아래)                                                                                                                                                                                                                             |
| `ui-setup.mjs`           | 브라우저 검사용 상태를 만들고 회원 쿠키를 파일로 남긴다                                                                                                                                                                                                                                                          |
| `ui-cdp.mjs`             | 시스템 Chromium을 DevTools 프로토콜로 조종해 대시보드 버튼 클릭·화면 갱신·콘솔 오류 확인. 세미나 신청 폼이 신청자를 발표자로 고른 채 열리는지도 본다                                                                                                                                                             |

### 시드 API와 가드

앱은 `DATA_BACKEND=memory`일 때 데이터를 서버 프로세스 메모리에만 둔다 — 밖에서 넣거나
원본을 볼 길이 없다. 시드 API(`/api/__probe`)가 그 창구다: `reset`(저장소와 **모든 테이블
캐시**를 비움), `put`/`seed`(문서를 그대로 넣음), `GET`(저장된 원본 읽기).

운영에 있으면 인증 없이 데이터를 바꾸는 구멍이므로 두 겹으로 막는다.

1. **레포의 `src/`에 없다.** 운영 빌드에 코드 자체가 들어가지 않는다 — 이것이 주 방어선이다.
2. 파일 안의 가드: `dev`(`$app/environment`, 운영 빌드에선 항상 false) · `DATA_BACKEND=memory` ·
   `x-probe` 헤더 토큰이 모두 맞아야 응답하고, 아니면 404.

`GET`이 돌려주는 것은 **zod 기본값이 씌워지기 전** 원본이다(옛 행에는 `posterKey`·
`schedule` 같은 필드가 없을 수 있다). 판정할 때 앱 규칙을 맞출 것. `real.mjs`는 백업의
세미나에 마이그레이션 20260928000100의 규칙(`publicationStatus` 없음 → `published`)을
적용한 뒤 시드한다 — 배포 순서와 같다.

## 실행

필요한 것: `node`(>=22), `rsync`, `git`, 레포에서 `pnpm install` 한 번. 브라우저 검사만 `chromium`
(`CHROMIUM` env로 경로 지정 가능).

```bash
# 터미널 1 — 수정본 (현재 작업 트리)
scripts/measure/start.sh                        # :5199

# 터미널 2 — 대조용 (커밋된 코드). 전후 결과 차이가 전부 의도한 수정이어야 한다
scripts/measure/start.sh --ref HEAD --port 5198

# 터미널 3
node scripts/measure/scenarios.mjs                              # BASE 기본 :5199
BASE=http://127.0.0.1:5198 node scripts/measure/scenarios.mjs   # 대조
RUNS=12 node scripts/measure/race.mjs
node scripts/measure/ui-setup.mjs && node scripts/measure/ui-cdp.mjs
bash scripts/ops/smoke-routes.sh                                # 레포 기존 도구도 같은 서버에
BASE=http://127.0.0.1:5199 node scripts/ops/ops-render-check.mjs
```

- 작업 디렉터리는 `$MEASURE_DIR`(기본 `$TMPDIR/snumps-measure`) — 복사본, 서버 로그
  (`<이름>.log`), 시계 오프셋, 브라우저 프로필이 여기 생긴다. 레포에는 아무것도 쓰지 않는다.
- 코드를 고친 뒤에는 `start.sh`를 다시 실행하면 복사본이 갱신된다. **떠 있는 서버에 복사본만
  바꾸면** Vite가 모듈을 다시 불러오며 메모리 저장소가 비워진다 — 몇 초 기다린 뒤 돌릴 것.
- 스크립트는 서로 상태를 공유한다(같은 서버·같은 시계). 한 서버에는 한 번에 하나만 돌린다.
  서버가 여러 대여도 **시계 파일은 하나**다.
- 모든 스크립트는 실패가 있으면 종료 코드 1.

### 날짜와 학기

시나리오는 실행 날짜와 무관하다. 서버 시계를 **현재 학기 시작 + 30일 10:00 KST**에 고정하고
모든 일정을 거기서 잰다(`lib.mjs`의 `ANCHOR`, `at(days)`, `TERM`). 재가입 시나리오는 직전
학기(`PREVIOUS_TERM_AT`)로 옮겼다 돌아온다. 끝나면 시계를 실제 시각으로 되돌린다.

## 실데이터 (`real.mjs`) — 개인정보

```bash
node scripts/measure/real.mjs backups/supabase-<시각>.json   # ops-backup-db.mjs 산출물
```

스냅숏(이메일·전화번호·학번 포함)을 **로컬 메모리 서버에만** 올린다. 출력은 상태코드·개수·
id뿐이고 이름·이메일·전화번호는 찍지 않는다. 실회원 이메일로 세션을 위조해 각자의
대시보드를 렌더하므로, 스냅숏을 다룰 권한이 있는 사람만 돌릴 것. 이 스크립트는 복사본의
데이터를 **실제로 지운다**(숨겨진 세미나 삭제 검사) — 메모리 서버라 원본과 무관하다.

## 한계

- 메모리 백엔드다 — 다만 PGlite(인프로세스 Postgres)가 운영과 같은 마이그레이션을 적용하므로 `flow_*`
  함수와 그 잠금·규칙은 운영과 같은 SQL로 돈다. 재현하지 않는 것은 Supabase 고유 동작이다: RLS와 역할별
  실행 권한(PGlite에는 Supabase 역할이 없다), PostgREST 경유, 네트워크 지연, 여러 연결 사이의 실제 경합
  (PGlite는 연결 하나로 문장을 차례로 실행한다).
- 메일은 발송 시도까지만 본다(토큰 발급에서 실패). 본문·수신자 검증은 단위 테스트 몫이다.
- 위조 세션은 Auth.js의 로그인 과정(OAuth, 도메인 검사 콜백)을 거치지 않는다.
