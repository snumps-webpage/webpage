방법: 독립 2라운드. R1 = 플랫폼 사실 실검증(20건 웹 검증) + 목적 오류 + 콩팥 오류(CODE-REVIEW 보존 목록 대조).

### 🟠 명세 정정 필요 (설명 후 일괄 반영 승인 요청)

- **"137테스트 무수정" 과대 약속** — 실제 수정 필요분 실측: 포이즌 픽스처 2건(바이트+키 표면 직주입), 감사 검증의 키-카운팅 3건, (D-1=Firestore 시) firebase 목 3파일, 목 경로 교체 12파일. 게이트는 유지하되 스코프 정직화 (R1-11)
- `createSignedUploadUrl` 의미론 차이 5종 — 만료 고정 2h, Content-Type 미서명(승격 검증이 유일 방어선으로 승격됨 — 다행히 이미 그렇게 설계됨), 기존 경로 발급 400, upsert 토큰 서명, 버킷 한도 강제 여부 미검증 → **T3 착수 전 실측 테스트 게이트** (R1-2)
- `move()` "원자적" 문구 삭제 (R1-3) / If-None-Match 유사 구현의 삭제-케이스 구멍 → version 컬럼 SELECT 비교 방식으로 (R1-4) / TOAST 압축 근거 문구 정정 (R1-7)
- `SUPABASE_SERVICE_ROLE_KEY` 명명 — legacy JWT 체계 2026년 말 deprecate 예고 → `sb_secret` 신 체계 기준으로 (R1-5)
- egress 회계(uncached 5GB+cached 5GB 별도), Firebase Storage 차단 시점(2026-02 전면), cron-job.org 25회 문구("in some cases")·64KB 응답 상한·canonical URL 등록 수칙 (R1-5·8·9)
- 잡 3 "keep-alive 겸함" 과장 — Storage 작업이 활동 계상되는지 미문서 → 1행 SELECT 한 줄 추가로 문장 참으로 (R1-12)
- **§1-3 계약 문면 충돌** — gzip·버전 관리·S3 경로가 API-SPEC 문면에 있음: "보존"이 아니라 "저장 형식 절 개정"으로 선언해야 무손상 원칙 경계가 정직 (R1-14)
- KMS 상실(PII 공유 암호화로 후퇴)·CloudTrail 상실(인프라 접근 감사 불능, 무료 로그 1일) — §6 트레이드오프 목록에 명기 (R1-17·16)
- 1GB Storage 산수 부재 — 50MB PDF 20개로 소진 가능, 실측+학기당 증가 전망 필요 (R2-5)
- 모니터링 장 부재 — 쿼터 접근 알림 수신자, DB 500MB 초과 시 read-only(전 mutate 500) 경고 경로 (R2-7)
- 계정 소유 규율 — 구 OPERATOR-TODO의 공용 메일·MFA 원칙이 신규 3계정에 미승계 + 자격증명 인벤토리 (R2-8)
- MIG §8 댕글링 — snumps-migration 역할 참조, P0-2 덤프 목적지, UPSERT의 Zod 게이트·version 초기화 (R2-4)
- 작업 목록 구멍 — 잡 3 구현체(메인터넌스 서비스+백업 라이터)·복구 절차 문서화의 소유 태스크 부재, BE-35 확정 표·부록 금지 1항·TF state 잔여 항목 등 T8 열거 목록화, vercel.json 처분 미기재 (R2-9~12)
