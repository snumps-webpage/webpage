# SNUMPS 웹페이지 — 최종 기능 명세 (v1.0)

> **목적**: 최종적으로 웹페이지에 존재하게 될 전체 기능을 확정하는 문서.
> 이 문서가 검토·확정되면, 각 기능 단위로 API 명세를 작성한다.
>
> **종합 출처** (표기 규칙):
>
> - `[현행]` — `main` 브랜치에 이미 구현되어 있는 기능
> - `[S]` — `seminar` 브랜치(`fd7e482`) 이주 대상 (`docs/seminar-migration-spec` 브랜치의 `seminar-events.md`)
> - `[N]` — Notion 대체 이주 대상 (`docs/notion-migration-plan` 브랜치의 `notion-*.md` 4종)
> - `[신규]` — 위 문서들이 요구하나 어디에도 아직 없는 기능
>
> 구현 코드의 효율화·리팩터링은 별도 세션에서 진행 중이므로, 이 문서는 **구현 방식이 아니라
> 기능의 존재와 동작 요건**만 규정한다.

## 0. 확정된 전제 (이주 문서에서 승계)

> 🔴 **최상위 전제: 데이터베이스는 Notion에서 AWS S3로 전면 이전한다.**
> 이 문서의 모든 기능은 S3 데이터 계층(§7 SYS-01) 위에서 동작하는 것을 전제로 명세한다.
> Notion은 이주 완료 시점에 읽기·쓰기 모두에서 제거된다.

| #   | 결정                                                                                                                                                                                                                              |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D0  | Notion을 온전히 대체한다. 편집·서빙 전부 앱으로 이전. 레코드 저장소는 AWS S3                                                                                                                                                      |
| D1  | 정적 문서(회칙 등)는 레포에 커밋해 빌드타임 서빙. 편집은 GitHub PR                                                                                                                                                                |
| D2  | 회원 명단은 현재 공개 범위(이름·학과·가입일·임원 이력) 그대로 공개 유지                                                                                                                                                           |

## 1. 사용자 역할

| 역할              | 정의                                                                | 접근 범위                             |
| ----------------- | ------------------------------------------------------------------- | ------------------------------------- |
| **게스트**        | 비로그인 방문자                                                     | 공개 영역(§3) 전체                    |
| **신청자**        | 로그인했으나 미가입/미승인 (`@snu.ac.kr` Google 계정)               | 공개 영역 + `/signup`, `/wait`        |
| **회원**          | 가입 승인 완료                                                      | 위 + 회원 영역(§4)                    |
| **발표자**        | 특정 세미나의 `Presenters`에 등록된 회원                            | 위 + 해당 세미나의 출석 관리(§5)      |
| **스터디 주최자** | 특정 스터디의 주최자로 등록된 회원                                  | 위 + 해당 스터디의 인원·출결 관리(§5) |
| **관리자**        | 회원 테이블에서 관리자 지위가 부여된 회원 (D4 — 하드코딩 명단 아님) | 전체 + 관리자 영역(§6)                |

### 1-1. 회원 지위 체계 (D4 세부 — 확정)

두 개의 독립 축으로 관리한다.

**① 지위(status) 축**

| 값         | 정의                                                                                   |
| ---------- | -------------------------------------------------------------------------------------- |
| **준회원** | 가입 승인된 초기 지위                                                                  |
| **정회원** | 승격된 지위. **정회원 취득 시 동문 지위를 함께 취득**                                  |
| **동문**   | 정회원 취득 이력에서 발생하는 **영구 지위**. 유고(박탈 처분)가 아닌 한 상실되지 않는다 |

**② 직책(임원) 축** — 지위 축과 **별개 요소**. 학기별 직책(회장·부회장·부장 등)을 회원에게 부여. 회장단 표시·관리자 판정이 여기서 파생.

> **경과 조치**: 이주 시 기존 회원을 정회원·동문으로 간주하지 않는다. 전원 준회원으로 시작하고,
> **활동 기록 DB 이주 완료 + 신규 회칙 제공 후** 회칙 기준으로 일괄 재분류한다.
> 재분류 전까지 지위 축은 접근 권한에 영향을 주지 않는다.

## 10. 미결 사항

**익명화 회원과 활동 이력 규칙은 보류** — 탈퇴 후 이름·학과 공개 여부, 내부 활동 통계 범위,
회원 ID 유지/대체, 임원 이력 보존 여부를 임원진이 확정해야 한다. 그 전에는 자동 익명화와 관련 공개 DTO를 구현하지 않는다.

**v0.8 확정**:

- ~~처리 완료 가입 신청 보존~~ → **전환 방식** — 승인 시 신청 내용을 회원 개인정보 DB로 전환하고 신청 행 제거. 신청 테이블에는 미처리 건만 존재
- ~~가입 신청 본인 철회~~ → **허용** — 승인 전 재로그인 시 `/wait` "신청 처리 중" 페이지 하단 철회 버튼
