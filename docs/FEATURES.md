## 🔐 인증과 접근

- **Google 로그인** — SNU Google Workspace 계정만 (AUTH-01): `@snu.ac.kr` 주소이면서 Google이 확인한 주소이고,
  `snu.ac.kr` Workspace가 발급한 계정. 전용 로그인 페이지 `/login`, 로그인 후 원래 페이지로 복귀(안전한 내부 경로만).
- **라우트 그룹 = 접근 존** — 공개 / 신청자 / 회원 / 관리자. 관리자 화면은 권한이 없으면 404.
- **학기별 등록제 (S9)** — 회원의 참여 권한은 이번 학기 등록에서 나온다. 미등록 동문은 회원 화면
  열람과 본인 설정만 가능하고, 그 외 미등록 회원은 재가입 신청이 필요하다.

## 🌐 공개 영역

- `/` — 비로그인 랜딩(논문 표지 형식, 현 회장단 연락처는 동의한 경우만).
- `/about/*` — 회칙(개정 이력 포함), 역대 임원진. 선거·재정·보도는 자료 준비 중 안내 페이지.
- `/archive/*` — 세미나(상세·사진 포함), 스터디, 활동, 갤러리, 프로젝트, 기타. 출석 명단은 공개하지 않는다.
- `/members` — 공개 회원 명부 (탈퇴자 제외, 개인정보 없음).
- 파일은 `/media/<key>`로만 제공 — 취소·미공개 세미나의 파일은 관리자에게만.

## 👥 회원

- **가입 신청** `/signup` → **대기** `/wait` (수정·철회 가능) → 관리자 승인 시 회원 등록 + 환영 메일.
- **대시보드** `/` — 이번 학기 활동과 참여 상태, 세미나 참가 신청·취소, 내 신청·스터디, 주최자 인계 제안, 내 정보 수정.
  참가 신청이 거부되면 이유(이미 시작됨, 더 이상 없음 — 새로고침, 등록 회원만 가능)를 알려 준다. 내 세미나 신청은
  세미나가 취소·삭제된 뒤에도 "취소됨"으로 남는다.
- **입력 검증** — 신청·설정·관리 폼은 틀린 필드를 한 번에, 각 필드 옆에 보여 주고 아무것도 저장하지 않는다.
- **알림 설정** `/settings/notifications` — 전체 공지 메일 수신 여부, 회장단일 때 전화번호 공개 여부.
- **탈퇴** `/settings/withdraw` — 3단계 확인, 즉시 접근 중지, 1개월 유예 동안 `/withdraw/pending`에서 취소 가능.
  진행 중인 스터디 주최자는 먼저 인계해야 한다. 유예 이후 처리(익명화)는 임원진 결정 전까지 **구현하지 않는다**.

## 🎤 세미나

- **신청** `/seminar/apply` — 정기/비정기, 소개·선수지식·소요 시간·선호 시기, 공동 발표자(신청자가 처음부터
  선택되어 있고 뺄 수 있다 — 발표자는 1명 이상), 외부 자료 링크, 포스터(자동 생성 또는 업로드).
  심사 전에는 `/seminar/edit/<id>`에서 수정·철회할 수 있다(정기/비정기·선호 시기를 그대로 불러온다).
- **수명주기** — 승인(신청자에게만 통보) → 일정 미정 → 일정 확정 → **공개**(활동·출석 이벤트 생성 + 공지 1회) → (취소).
  공지는 이번 학기 등록 회원과 동문 중 수신 동의자에게 간다(탈퇴 유예 중인 회원 제외).
  일정 변경·취소 공지는 이미 공지된 세미나에만 나간다. 취소해도 기록은 남는다.
- **발표자 출석 관리** `/events/manage` — 참가 신청자 중에서 출석을 표시. 다른 경로의 출석은 보존(merge).

- **개설 신청** `/study/apply` → 관리자 승인 → 주최자 지정. 새 신청서와 본인 신청 기록을 함께 표시하고, 검토 중 신청을 먼저 읽는다. `?/submit`·`?/withdraw`를 구분하며 JavaScript 없이도 실패한 입력과 제출·철회 결과를 확인할 수 있다. 승인 전에는 모집을 시작하지 않는다.

  회차 정정·취소, 주최자 인계(제안 → 수락). `/study/<id>/attendance`에서 회차별 출석.

  취소된 회차와 같은 일시로는 만들 수 없다.

## 🛠️ 관리자 (`/admin`)

- **대시보드** — 가입 신청, 세미나·스터디 신청, 출석 큐, 탈퇴 유예 목록. 30초 폴링(탭이 보일 때만).

- 거부된 관리자 작업은 오류 코드 대신 이유(서버 메시지 또는 코드별 안내)를 알림으로 보여 준다.
- **이벤트** — 새 출석 이벤트, 기존 활동에 연결.
- **메일** — 템플릿·발송 규칙·공용 변수 편집, 직전 버전 되돌리기, 테스트 발송.

### 세미나 신청 원고와 발표자 선택

`/seminar/apply`와 `/seminar/edit/[id]`는 운영 방식·발표 내용·진행 정보·발표자·선택 자료 순서로 읽는다. 발표자는 네이티브 체크박스로 선택하며 여러 `speakerIds` 필드를 제출한다. 기존 쉼표로 구분한 필드도 계속 받는다. 검증·저장 실패 때 원고와 고의로 비운 발표자 선택을 보존한다. 포스터 도구는 접힌 선택 항목이며 확정 일정 입력이 아니다. 입력/검색/전송 및 업로드와 다운로드는 서로 다른 동작이다.

### 가입 신청과 승인 대기

`/signup`·`/signup/edit`는 신청 계정의 읽기 전용 정보와 학번·연락처·배경지식을 구분한다. 검증·저장 실패 시 입력한 원고와 사용자가 선택한 동의 상태를 보존한다. 신청 접수는 승인과 구분하며 `/wait`에서 저장된 신청과 한국 시간의 접수 시각을 확인한다. 철회·개인정보 삭제는 대기 화면의 안내를 펼친 뒤 본인이 실행한다. 기존 계정·동의·소유권·중복 신청 검증을 유지한다.

### 공지 수신과 회장단 연락처 설정

`/settings/notifications`는 전 회원 공지 메일과 현 회장단의 공개 연락처를 구분한다. 메일의 수신 주소·적용 범위·개별 운영 알림 예외를 함께 읽고, 전화번호를 공개하려면 네이티브 안내를 펼쳐 방문자 공개 범위를 확인한다. 각 액션의 성공·실패 문구를 구분하고 전송 중 반복 제출을 막는다. 전화 공개의 `hide`는 명시적인 `true` 또는 `false`만 허용하며 누락·다른 값으로 비공개 번호를 자동 공개하지 않는다. 기존 본인 정보 대상·회원 권한·회장단 자동 공개 정책과 유효한 토글 동작은 유지한다.

### 발표자 출석부의 기록 정정

`/events/manage`는 GET 선택 폼으로 담당 세미나를 열고, 선택한 세미나를 native POST에서도 유지한다. 참가 신청자의 저장된 출석과 링크 요청의 승인/대기/거절 상태를 구분한다. 같은 세미나의 명부가 새로 도착하면 명시적인 미저장 선택을 유지하고 다른 저장 변경·새 신청자를 반영하며 사라진 신청자를 제거한다. 전송 중에는 선택·다른 작업을 막고 이전 세미나의 늦은 응답을 현재 출석부에 적용하지 않는다. native 실패도 valid 명부 안의 체크 선택과 결과를 복원한다. 이번 학기 등록 전에는 읽기 전용이며, 접수 종료 후 기록 정정은 기존처럼 가능하다. 공유 요청 링크는 접수 중일 때만 제공한다. 취소는 시작 전 네이티브 안내를 펼쳐 실행하며 기록 보존과 안내 메일 실패를 함께 알린다.

### 탈퇴 신청과 본인 철회

`/settings/withdraw`는 접근 제한·개인정보 처리·본인 이름의 세 확인 항목을 함께 읽고 native POST로 제출할 수 있다. 두 확인은 처음에 체크하지 않으며 실패 때 사용자가 실제 제출한 선택과 이름만 복원한다. 진행 중인 스터디 주최자는 기존처럼 인계를 먼저 해야 한다. 신청 후 `/withdraw/pending`는 1개월 유예 기준과 자동 익명화 집행 보류를 구분하며, 기존 정책대로 유예 종료 이후에도 본인이 철회할 수 있음을 안내한다. 저장 불가/전송 불확실성과 이미 처리된 상태를 구분하고 반복 제출·로그아웃 경합을 막는다. 삼중 확인·본인 대상·감사 로그·즉시 접근 제한·직전 지위 복원·메일 정책은 바꾸지 않는다.

### 관리자 회원 기록의 제출 상태

회원 상세의 기존 기본정보·지위·동문·비공개정보·직책·관리자·탈퇴 보존 동작은 일반 POST에서도 입력값과 해당 영역의 결과를 표시한다. 직책은 기존 `YY-1 직책` 한 줄 형식을 실제 textarea로 편집하며 빈 입력은 명시적 전체 해제다. 향상된 제출은 한 회원의 한 동작만 처리하고 조회 완료까지 잠근다. 저장한 영역만 서버 조회값으로 다시 채우며 다른 열린 영역의 초안은 유지한다. 자기 관리자 권한 회수 표시는 인증된 회원과 대상의 일치로 판단하고, 최종 권한 검사는 기존 서버 규칙에 남는다.

### 관리자 기록의 native 제출과 초안 복구

활동의 날짜 입력은 JavaScript formdata 변환 없이 KST 날짜로 처리한다. 현재 기록의 같은 KST 날짜를 보내면 실제 시작·종료 시각을 유지하고, 달라진 날짜만 기존 변경 규칙으로 처리한다. 연결된 세미나/스터디의 제목·일정 소유권 검사는 유지한다. 세미나 소개글 `description`과 비고 `note`를 각각 편집하며 공개 개요는 저장된 소개글을 읽는다. 발표자는 반복 checkbox와 기존 쉼표 형식을 모두 받으며 명시적 빈 선택은 해제, 생략은 유지다. 운영 선택 명단에 없는 저장된 발표자는 별도 기존 기록 선택으로 보여서 제목 편집만으로 이주 기록을 잃지 않는다. 지원되는 세미나 레코드 삭제는 UI에서 접근할 수 있고, 출석·참조·공개 활동 유지 여부는 기존 원자적 삭제 흐름이 판단한다. 네 기록 편집기는 대상/영역별 실패 초안을 복구하고 오류가 있는 대상은 펼쳐 보여 준다. 실제 스토리지·메일·OAuth/RLS 연동은 이 로컬 검증 범위에 포함하지 않는다.

### 임원진과 자동 메일의 기존 관리 경로

임원진의 학기/직위 선택은 일반 GET으로 조회하고, 같은 query 문맥을 named POST에 유지한다. 삭제된 직위는 새 조회의 배정 선택에서 빠지며 과거 roles 기록은 그대로 남는다. 공개 역대 회장단의 Current는 최신 기록이 아니라 실제 currentTerm과 일치하는 학기에만 붙는다.

메일의 기존 템플릿/변수/규칙 편집과 생성은 native details 안의 실제 form으로 접근한다. 각 대상 초안을 독립적으로 유지하며 다른 변수 저장, 규칙 변경, 테스트 결과로 관련 없는 편집 내용을 닫거나 지우지 않는다. 자신의 저장만 해당 영역을 서버값으로 다시 채우고 닫는다. 실패는 원문 입력과 체크 여부를 같은 영역에 복구한다. 향상된 제출은 재조회까지 한 요청만 처리하며 모든 쓰기 입력을 잠근다. 두 기존 발송 테스트는 각각 명시적 form/버튼으로 제공하고 실제 수신자·발송 규칙·서버 서비스는 변경하지 않는다. 본 개발 검증은 가상 수신자와 격리된 무전송 collector를 사용한다.
