# 코드 감사 (Code Audit)

`main` 코드베이스를 파일 단위로 검토하고, 각 검토 결과를 별도 에이전트로 검증하는 작업.

> **성격**: 한시적 작업 문서 디렉터리. `docs/MAINTAINING_DOCS.md`의 taxonomy 바깥이다.
> 감사가 끝나면 이 디렉터리는 삭제하고, 살아남을 내용은 `ARCHITECTURE.md`(구조적 결론),
> `CONTRIBUTING.md`(코딩 규칙), 그리고 실제 리팩터링 커밋으로 옮긴다.

## 무엇을 보는가

| 항목 | 예 |
|---|---|
| 코드 중복 | 같은 로직이 여러 파일에 복사됨 |
| 하드코딩된 파라미터 | 함수 안에 박힌 매직 넘버·문자열·TTL·URL |
| 확장 불가 구조 | 항목 추가 시 여러 곳을 함께 고쳐야 하는 설계 |
| clean code 위반 | 책임 혼재, 명명, 함수 길이, 부수효과, 오류 삼킴 |

**데이터·설정 파일은 코드와 기준이 다르다.** 분리해서 다룬다 — [SCOPE.md](./SCOPE.md) A2/A3.

## 절차

파일 하나마다:

1. 파일 전체를 읽고 리뷰 → `files/<상대경로>.md`
2. **검증 에이전트 dispatch** — 지적이 사실인지, 과도하지 않은지, 놓친 게 없는지 냉정하게
3. 에이전트 결과 반영 → 커밋

**한 파일 = 한 문서 = 한 커밋 = 한 검증.** 묶지 않는다. 묶으면 검증 품질이 떨어진다.

## 원칙

- **지적은 근거와 함께.** "복잡하다"가 아니라 "X와 Y가 같은 로직이고, Z를 추가하려면 둘 다 고쳐야 한다"
- **과도한 지적을 경계한다.** 605행짜리 동아리 사이트다. 엔터프라이즈 기준을 들이대지 않는다
- **동작 변경 제안과 구조 제안을 구분한다.** 전자는 회귀 위험이 있다
- **이미 알려진 것은 다시 적지 않는다.** `svelte-check` 40 errors는 기준선이다
