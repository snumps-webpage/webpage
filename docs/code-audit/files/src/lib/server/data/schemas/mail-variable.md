# `src/lib/server/data/schemas/mail-variable.ts` (24줄)

**접두사 `LA20-`** · `mail-variables` 테이블 행 스키마 — 전 템플릿 공용 `{{key}}` 값(코드 기본값 오버라이드·관리자 정의).

## LA20-1 🟡 변수 이름 규칙이 세 곳에 복사돼 있다

13행 `key: z.string().regex(/^[a-zA-Z][a-zA-Z0-9]*$/)`와 같은 정규식이

- `services/mail-admin.ts:557` `if (!/^[a-zA-Z][a-zA-Z0-9]*$/.test(key))` — 친절한 오류 문구를 내는 검사
- `(admin)/admin/mail/+page.svelte:388` `pattern="[a-zA-Z][a-zA-Z0-9]*"` — 브라우저 검사

에 있다. 렌더러는 또 다른 규칙 `\{\{\s*(\w+)\s*\}\}`(`template-store.ts:273,315`)를 쓰는데 이것은 상위집합이라 저장된
어떤 키도 렌더된다 — 이 방향은 옳다.

결과: 규칙을 바꾸려면(예: 밑줄 허용) 세 곳. 스키마만 바꾸면 서비스가 먼저 거부하고, 서비스만 넓히면 게이트가 일반
`VALIDATION_FAILED`로 거부해 관리자는 친절한 문구 대신 "요청을 처리할 수 없습니다"를 본다. 처방: 정규식을 도메인
상수 하나로(화면도 쓸 수 있게) 두고 셋이 가져온다. 동작 변경 없음.

## LA20-2 🟡 `previous` 스냅숏 모양이 이름 없이 인라인이다 — `LA19-1`과 같은 형태

17-20행 `previous: z.object({ value, description })`는 14-15행의 부분집합이고, 서비스가 세 번 손으로 나열한다 —
`mail-admin.ts:573-575`, `:584`, `:602-607`(스왑). 필드를 더하면 조용히 빠지는 기전도 같다(`LA19-1` 결과 문단).
처방도 같다(버전 스키마 한 번 정의). 동작 변경 없음.

## 확인했고 지적하지 않은 것

- **런타임 변수와 키가 겹치면 이벤트 값이 우선(7-8행)** — 주석과 렌더러 병합 순서가 일치하는지는
  `template-store.ts` 리뷰 몫이다. 이 스키마가 말하는 계약으로는 결함이 없다
- **`value: z.string()`(14행) 빈 값 허용** — 변수를 비워 두는 것은 합법적인 운영 선택이다
- **`description: z.string().default("")`(15행)** — 없음과 빈 설명의 의미가 같다(`LA19` 확인 항목과 같은 판단)
