# `src/lib/server/data/schemas/mail-template.ts` (28줄)

**접두사 `LA19-`** · `mail-templates` 테이블 행 스키마 — 코드 기본 문구의 오버라이드와 커스텀 템플릿, 직전 버전 1단계.

## LA19-1 🟡 "버전에 속하는 필드"에 이름이 없어, 서비스가 같은 3-필드 스냅숏을 다섯 곳에서 손으로 쓴다

21-24행 `previous: z.object({ subject, body, enabled })`는 현재 행의 `subject`·`body`·`enabled`(17-19행)와 같은 필드의
부분집합을 이름 없이 인라인으로 다시 선언한다. 어떤 필드가 "되돌리기 대상"인지를 가리키는 스키마·타입이 없으므로
서비스가 매번 나열한다 — `mail-admin.ts:119`, `:129-133`, `:151-157`(되돌리기 스왑: 세 필드를 꺼내고 세 필드로
다시 담는다), `:237`, `:244-248`. 기본 문구에서 만든 첫 스냅숏에 `enabled: true`를 박는 것도 두 번(`:119`, `:237`).

결과: 되돌리기 대상 필드를 하나 더하면(예: 발신자 표시명) 스키마 두 곳 + 서비스 다섯 곳을 모두 고쳐야 한다.
하나라도 빠뜨리면 `LA17-1`과 같은 방식으로 **조용히** 빠진다 — `previous`가 비엄격 객체라 모르는 키를 벗기고, 스왑은
적힌 필드만 옮긴다.

처방: `const TemplateVersion = z.object({ subject, body, enabled })`를 한 번 정의해 현재 행은 `.merge`/`.extend`로,
`previous`는 `TemplateVersion.nullable()`로 쓰고, 서비스는 `pickVersion(row)` 한 함수로 스냅숏을 뜬다. 동작 변경 없음.
같은 형태가 `mail-variable.ts`에 있다(`LA20-2`).

## 확인했고 지적하지 않은 것

- **`name`이 `previous`에 없다** — 커스텀 템플릿 이름은 생성 때만 정해지고(`mail-admin.ts:165-190`) 이후 바꾸는
  경로가 없다(`saveMailTemplate` 입력에 `name`이 없다, `:89-94`). 버전 대상이 아닌 것이 맞다
- **`name: z.string().default("")`(16행)** — 오버라이드 행은 빈 이름이고, 목록이 `t.name || t.key`로 표시한다(`:73`).
  기본값이 "필드 없음"과 "명시적 빈 값"을 구분하지 않지만 두 경우의 의미가 같으므로 문제되지 않는다
  (`seminar.ts:88-96`이 기본값을 뺀 사례는 두 의미가 **달랐던** 경우다)
- **`key` 유일성** — 서비스가 `findIndex`로 upsert한다. 스키마로 표현할 수 없는 행 간 불변식
- **"행 삭제 = 기본 문구로 복원"(9행)** — `deleteMailTemplate`은 기본 키 삭제를 거부한다(`:196-201`). 주석의 "복원"
  경로는 관리 화면이 아니라 운영 수동 조작을 가리키는 셈이다. 주석이 틀린 것은 아니어서 지적하지 않는다
