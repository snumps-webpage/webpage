# `src/lib/server/route-policy.ts` (23줄)

**접두사 `LB07-`** · URL 경로 접두사로 "회원 가드를 건너뛸 경로"를 판정하는 `shouldBypassMembershipGuard`와 세그먼트 경계 비교 `matchesPathRoot`.

## LB07-1 🟡 존 가드가 대체한 접두사 판정기가 테스트에 붙들려 살아 있다 — 그리고 이미 틀렸다

> **검증 정정**: 결론·등급 유지, 두 번째 결과 항목을 좁힌다. `PRIORITY.md:247`은 이 테스트를 가드 커버리지로 **세지 않았다** —
> 그 줄은 W-9("`api/` 라우트 테스트 0/7")의 근거로 "두 테스트는 존 분류만 보므로 엔드포인트를 덮지 않는다"고 적은 것이다.
> 틀린 것은 `route-policy.test.ts`를 "존 분류" 테스트라고 **묘사**한 부분이다(그것은 운영에서 돌지 않는 접두사 판정기를 본다).
> "죽은 테스트가 커버리지로 세어진다"는 과장이고, 정확한 서술은 "죽은 테스트가 살아 있는 가드의 테스트처럼 묘사되어 있다"이다.
> 운영 호출부 0(`route-policy.test.ts`만 import), 생성 `b39ec62`(08-28)·존 재구축 `a8c0695`(08-29), 표의 세 행은 모두 확인했다.

운영 호출부가 **0**이다. 이 파일을 import하는 것은 `route-policy.test.ts` 하나뿐이다(`grep -rn "route-policy\|shouldBypassMembershipGuard\|matchesPathRoot" src`).
생성은 `b39ec62`(2026-08-28), 바로 다음 날 `a8c0695`가 접근 제어를 라우트 그룹 존으로 재구축했다 — `zone.ts:4`: "Route groups **replace prefix matching**."

죽은 판정기이지만 내용은 존 체계와 이미 어긋난다.

| 경로           | `shouldBypassMembershipGuard` | 실제 존 (`zone.test.ts` `REGISTERED`)   |
| -------------- | ----------------------------- | --------------------------------------- |
| `/media/...`   | `false` (가드 대상)           | `(public)` — `/(public)/media/[...key]` |
| `/favicon.ico` | `true` (8행)                  | 라우트 없음                             |
| `/auth/...`    | `true` (10행)                 | Auth.js 핸들 — 라우트 그룹 밖           |

결과는 두 가지다.

- **공개 경로 목록이 두 벌**(1-9행, 그리고 `(public)` 그룹 디렉터리)이고 하나는 갱신되지 않는다. 누가 이 함수를 "공개 경로인가"의 판정으로 다시 쓰면 `/media`에서 틀린다
- **죽은 테스트가 커버리지로 세어진다.** `PRIORITY.md:247`은 "`zone.test.ts`·`route-policy.test.ts`는 존 분류만 본다"고 적어, 운영에서 돌지 않는 판정기의 테스트를 가드 커버리지 목록에 올렸다

처방: 파일과 테스트를 삭제한다(동작 변경 없음). `matchesPathRoot`의 세그먼트 경계 비교가 필요한 곳은 `zone.ts:152`(LB06-4)이므로, 필요하면 그쪽으로 옮긴다.
