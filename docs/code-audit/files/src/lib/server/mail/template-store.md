# `src/lib/server/mail/template-store.ts` (318줄)

**접두사 `LB13-`** · 자동 메일 템플릿의 코드 기본 문구 + 공용 변수 기본값, DB 오버라이드를 우선하는 렌더(`{{var}}` 치환).

## LB13-1 🟠 템플릿·변수 조회 실패 시 코드 기본값으로 **열린 채** 떨어진다 — 꺼 둔 메일이 옛 문구로 나간다

297-302행: `getTable("mail-templates")`가 던지면 기본 키는 코드 문구로 렌더된다. 293행의 `enabled=false`
검사는 **조회가 성공했을 때만** 일어나므로, 관리자가 끈 메일(예: `application-rejected`)이 다시 발송되고
고친 문구는 코드 원문으로 돌아간다. 266-268행(`getGlobalMailVariables`)도 같다 — 관리자가 바꾼 채팅방 링크가
`$lib/constants`의 옛 링크로 돌아가 **만료된 초대 링크**가 환영 메일에 실린다.

`fetchRows`는 행 하나가 스키마를 어기면 테이블 전체 읽기를 던진다(`data/tables.ts:106`). 따라서 이것은 일시
장애의 문제가 아니라, 잘못된 행 하나가 **모든 템플릿**을 조용히 기본값으로 되돌리는 지속 상태가 될 수 있다.

279-280행이 적은 근거 "메일이 본 동작을 막으면 안 된다"는 폴백 없이도 성립한다 — 호출부
`emitMailEvent`가 모든 예외를 잡는다(`dispatch.ts:174-182`). 폴백이 실제로 고르는 것은 "관리자가 끈 것을 보낸다"이다.
같은 형태가 `dispatch.ts:126-132`에 있다(`LB11-2`).

처방: 조회 실패 시 `null`(발송 안 함)로 돌리고 호출부가 `false`를 기록. **동작 변경.**

## LB13-2 🟡 템플릿 문구에 도메인 규칙과 운영 상태가 박혀 있다

229행 "신청일로부터 **1개월** 후 … (**현재 자동 삭제는 보류 상태**)".

- 유예 기간은 `core/time.ts:7-8` `WITHDRAWAL_GRACE_MS`(30일)가 "single definition"이라고 선언한 규칙이다.
  여기는 그 두 번째 표기이고, 값도 "1개월"과 30일로 이미 다르다
- "자동 삭제는 보류 상태"는 코드의 성질이 아니라 **운영 현황**이다. 자동 삭제가 켜지는 날 이 문장은 거짓이 되고,
  관리자가 이 템플릿을 한 번이라도 저장했다면 그 거짓은 DB 오버라이드(`mail-admin.ts:111-121`)에 복사돼
  코드를 고쳐도 남는다

처방: 유예 기간은 공용 변수(`graceDays`)로 발송 시점에 채우고, 운영 현황 문장은 빼거나 변수로. **문구 변경.**

## LB13-3 🟡 `seminar-approved`가 신청자에게 지켜지지 않을 수 있는 약속을 한다

112행 "일정이 확정되거나 이후 변경되면 **별도 안내 메일을 보내드립니다**" — 수신자는 신청자(당사자)다.
그러나 공개·일정 변경 메일의 기본 규칙은 `members-opted-in`뿐이고(`events.ts:120-122,129-134`), 그 집합은
"수신 동의 ∧ (이번 학기 등록 ∨ 동문) ∧ 탈퇴 아님"이다(`dispatch.ts:63-87`). 공지 수신을 끈 신청자,
이번 학기 미등록 비동문 신청자는 **자기 세미나의 일정 안내를 받지 못한다.**

처방: 문구를 "홈페이지에 게시합니다"로 줄이거나, 공개·변경 이벤트에 `party`(발표자) 규칙을 추가. 어느 쪽이든 **동작/문구 변경.**

## LB13-4 🟡 변수 토큰 문법이 세 곳에 있고, 이미 서로 다르다

273행(`interpolate`)과 315행(`extractVariableTokens`)이 같은 정규식 `/\{\{\s*(\w+)\s*\}\}/g`를 따로 쓴다.
변수 **이름** 문법은 `services/mail-admin.ts:557` `/^[a-zA-Z][a-zA-Z0-9]*$/`로 또 하나다.

`\w`는 밑줄과 숫자 시작을 허용하지만 변수 저장은 거부한다. 관리자가 템플릿에 `{{my_link}}`를 쓰면
렌더는 토큰으로 인식하고(`\w`), 같은 이름의 변수는 **만들 수 없으며**(557행), 결과는 매번 빈 문자열이다
(273행 `?? ""`) — 오류 없이.

처방: 토큰 정규식과 이름 문법을 한 상수로. 이름 문법을 하나로 맞추는 것은 **동작 변경**(어느 쪽으로 맞추느냐에 따라).

## LB13-6 🟡 `MailTemplateKey`는 `string`이고 아무도 쓰지 않는다

236행 `keyof typeof MAIL_TEMPLATE_DEFAULTS` — 26행이 타입을 `Record<string, MailTemplateDefault>`로 선언했으므로
결과는 `string`이다. 저장소 전체에서 참조가 없다(`grep MailTemplateKey`). 좁은 키 타입처럼 보이는 이름이
실제로는 아무것도 좁히지 않는다. `events.ts`의 `MailEventKey`와 같은 원인(`LB12-1`).
286-287행의 `as MailTemplateDefault | undefined` 캐스트도 같은 선언 방식의 부산물이다.

처방: `satisfies Record<string, MailTemplateDefault>`로 선언해 키 유니언을 살리거나, 타입을 지운다. **구조만.**
