# `src/lib/server/services/asset-access.ts` (64줄)

**접두사 `LB17-`** · 자산 키 하나의 접근 등급(`public`/`admin`/`none`) 판정. 유일한 소비자는
`/media/[...key]`(`(public)/media/[...key]/+server.ts:46`)다.

## LB17-1 🟠 "어느 기록이 어느 자산 키를 갖는가"의 열거가 `asset-cleanup.ts`와 따로 있다

19-63행과 `asset-cleanup.ts:5-21`이 **같은 네 표·같은 다섯 필드**를 각자 훑는다:

| 필드                                  | 여기  | `asset-cleanup.ts` |
| ------------------------------------- | ----- | ------------------ |
| `seminars.posterKey/materials/photos` | 35-38 | 14                 |
| `seminar-requests.posterKey`          | 55    | 17                 |
| `studies.photos`                      | 60    | 18                 |
| `gallery-dinner.photos`               | 61    | 19                 |

자산을 담는 필드를 하나 추가하면(스터디 자료, 회식 포스터 …) 두 파일을 함께 고쳐야 한다.
그리고 **빠뜨렸을 때의 실패 방향이 반대다**:

- 여기서 빠뜨리면 `none` → 404. 닫힌 쪽이고 화면에서 바로 보인다
- `asset-cleanup.ts`에서 빠뜨리면 그 키는 "참조 없음"으로 보여 **아직 쓰이는 파일을 지운다.** 열린 쪽이고 조용하다

두 파일이 서로의 존재를 언급하지도 않는다. 필드 → 판정 규칙의 표 하나(예: `{table, fields, access(row)}`)를
두고 판정과 참조 수집이 그것을 공유하면 추가는 한 줄이다. 구조만.

## LB17-3 🟡 `key.includes("..")`는 논리적으로 불필요하고, 틀린 거절만 만들 수 있다

> **검증 정정**: 주장을 좁히고 처방을 바꾼다. 등급 🟡 유지.
> (1) **"논리적으로 불필요"는 틀렸다.** 판정은 키를 **문자열로** 기록과 비교하지만, 라우트는 같은 문자열을
> 저장소의 **경로로** 쓴다(`media/[...key]/+server.ts:46,55` → `createSignedAssetUrl(key)`). 기록에 `a/../b` 같은
> 경로 조작 세그먼트가 들어 있으면(이주 사고·원시 편집) 판정 대상과 실제로 서명되는 객체가 달라질 수 있다.
> 이 줄은 "문자열 동일성 = 객체 동일성"을 보장하는 유일한 장치이므로 소속 판정이 대신하지 못한다.
> (2) **남는 결함은 과잉 범위다** — 세그먼트(`split("/").includes("..")`)가 아니라 부분 문자열을 보므로
> `report..v2.pdf` 같은 무해한 이름도 거절한다.
> (3) 초판의 근거 "이주분은 slugify를 거치지 않는다"는 사실이 아니다. 이주 스크립트도 키를
> `${prefix}/${slugify(name)}-${sha8}.${ext}`로 만들고(`scripts/migration/10-assets.ts:226`,
> `scripts/migration/lib.ts:309-318` — `.`을 `-`로 바꾼다), 새 업로드도 같다(`services/uploads.ts:64-78`;
> 초판의 `uploads.ts` 경로는 `services/` 아래다). 레이아웃의 `decodeURIComponent`는 그 흔적이 아니다.
> 다만 "지금 그런 키가 없다"는 감면 근거가 아니므로(README 판정 기준) 과잉 거절 자체는 그대로 지적한다.
> **처방 정정**: 줄을 지우지 말고 세그먼트 검사로 좁힌다.

16행. 이 함수의 실제 방어는 **정확한 소속 판정**이다 — 키가 어떤 기록 필드의 원소와 같지 않으면
`none`이다. 경로 조작 문자열은 어떤 기록에도 저장돼 있지 않으므로 이 줄 없이도 `none`이 된다.

이 줄이 바꾸는 결과는 하나뿐이다: **기록에 실제로 있는** `..` 포함 키(`report..v2.pdf` 같은 이주분 파일명 —
새 업로드는 `slugifyFilename`이 막지만 `uploads.ts:64-77`, 이주분은 그렇지 않다; 레이아웃이
`decodeURIComponent`로 이름을 푸는 것이 그 흔적이다 `archive/+layout.server.ts:28`)를 404로 만든다.
`asset-access.test.ts:228`이 이 줄을 단언하지만, 같은 단언은 소속 판정만으로도 통과한다.
지우면 동작이 바뀐다(그런 키가 열린다) — 의도대로의 변화다.

## 확인했고 지적하지 않은 것

- **가장 엄격한 쪽을 고르는 병합(28-32행)** — `restrict`는 한 번 `admin`이 되면 되돌아가지 않고,
  `public`은 `none`만 올린다. 스터디·회식과 겹쳐도 `admin`이 이긴다. 26-27행 주석은 "세미나끼리"라고
  좁게 적지만 코드는 전 소유자에 대해 같은 규칙이다 — 코드 쪽이 옳다
- **신청 포스터의 예외(53-58행)** — 세미나가 이미 그 키를 가지면 신청은 판정에서 빠진다. 세미나가
  미공개면 세미나 자체가 `admin`을 주므로 예외가 권한을 넓히는 경우가 없다. 승인의 `posterKey` 상속이
  보통 경로라는 설명(`asset-access.test.ts:179-206`)과 일치한다
- **스터디·회식 사진이 상태와 무관하게 공개인 것** — 레이아웃이 스터디를 상태 필터 없이 전부 싣는다
  (`archive/+layout.server.ts:140`). 화면 규칙과 같다. `StudyStatus`에 비공개 상태가 없다
- **요청마다 표 네 개를 읽는 것** — `getTable` 캐시를 탄다. 판정이 캐시 창만큼 늦을 수 있으나
  서명 URL 수명(300초)과 이미지 최적화 캐시(24시간, `svelte.config.js:20-23`)가 이미 더 긴 회수 지연을 가진다.
  이 함수가 병목이 아니다
- **404로만 거절하는 것** — 라우트의 결정(존재 사실 비노출). 이 함수는 등급만 낸다
