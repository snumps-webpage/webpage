# `src/lib/domain/semester-order.ts` (17줄)

## LC14-1 🟡 형식 밖의 학기를 연도 자리에서는 맨 앞으로, 반기 자리에서는 맨 뒤로 보낸다

> **검증 정정**: 결함(형식 밖 입력에 설계된 자리가 없다)과 🟡는 유지하고, **메커니즘 설명을 고친다.** 제목의 "연도 → 맨 앞 / 반기 → 맨 뒤"는
> 표시 순서(역순)와 비교자 순서를 섞어 말한 것이다. 같은 틀로 보면 반기 쪽 `?? 99`는 **항상** "그 해의 가장 최근"이고, `"Unknown"`의 연도 쪽도
> "가장 최근"이라 둘은 같은 방향이다. 실제 불일치는 연도 쪽의 자리가 **문자에 따라 갈린다**는 것이다 — 실측(`compareSemesters(b, a)` 표시 순서):
> `["Unknown","26-1","25-2"]`(영문자 → 맨 위), `["26-1","25-2","#1"]`·`["legacy","26-1","25-2",""]`(구두점·빈 연도 → 맨 아래),
> `["26-1","25-2","2025-2","19-1"]`(네 자리 연도는 `"2025" < "25"`라 2019년과 2025년 사이로 끼어든다). 반기 쪽도 `HALF_ORDER`가
> 평범한 객체라 `"26-constructor"`·`"26-toString"`은 `?? 99`가 아니라 함수 값을 얻어 비교 결과가 `NaN`이 된다(정렬은 `0`으로 취급).
> 처방(형식 밖을 한 자리로)은 그대로 맞다.

비교자는 입력이 `SEMESTER_PATTERN`이 아닐 때를 두 군데서 다르게 처리한다.

- 반기(16행): 모르는 반기는 `?? 99` — **같은 해의 겨울보다도 뒤**, 즉 그 해의 "가장 최근"으로 친다
- 연도(15행): `ay.localeCompare(by)` — 연도 자리가 숫자가 아니면(`"Unknown"`, `"legacy"`) 문자 비교에서 **숫자보다 뒤**가 된다.
  표시 순서는 역순(`compareSemesters(b, a)`, `public-content.ts:108,130`, `archive/+layout.server.ts:113,141`)이므로
  이 행은 목록 **맨 위**, 모든 실제 학기보다 앞에 온다(실측: `["Unknown", "26-1", "25-2"]`)

한 비교자 안에서 "형식 밖"이 한 번은 최신 쪽 끝, 한 번은 연도 안의 최신 쪽 끝으로 가는데, 어느 쪽도 설계된 자리가 아니다.
`16행`의 `?? 99`는 이 함수가 형식 밖 입력을 **받아들일 의도**가 있다는 표시라서, 연도 쪽 처리가 빠진 것은 누락이다.
`"Unknown"`은 가상의 값이 아니다 — 같은 디렉터리의 `term.ts:34`가 학기 자리에 돌려주는 값이고,
`public-content.test.ts:25`의 `"legacy"`는 `formatArchiveTerm`이 명시적으로 받아 주는 입력이다.

지금 호출부는 모두 `Semester` 게이트(`schemas/common.ts:17`)를 통과한 값을 넘긴다. 판정 기준대로 감면 근거는 아니다 —
인자가 `string`이고 이 모듈은 브라우저 안전 공용 규칙이다.

처방: 형식 밖을 한 자리로 모은다 — 예: 두 값이 모두 형식을 만족할 때만 연도(`Number`)·반기로 비교하고, 형식 밖은 항상
맨 끝(가장 오래된 쪽)으로. 형식 안의 순서는 그대로다. **현행 데이터 기준 구조 변경**, 형식 밖 입력의 자리만 **동작 변경**.
부수로 15행의 `localeCompare`(인자 없이 실행 환경 기본 로캘)는 두 자리 숫자 문자열에는 `<` 비교와 결과가 같다 —
의도가 "사전순"이 아니라 "연도순"이면 `Number(ay) - Number(by)`가 그 의도를 말한다.
