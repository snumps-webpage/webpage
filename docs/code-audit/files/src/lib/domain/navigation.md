# `src/lib/domain/navigation.ts` (15줄)

**접두사 `LC12-`** · `safeInternalRedirect` — 로그인 후 돌아갈 `?redirect=` 값을 같은 사이트의 경로로만 좁힌다(오픈 리다이렉트 차단).
짝 테스트 `navigation.test.ts`(35줄)를 규칙의 일부로 읽었다.

지적 없음.

## 확인했고 지적하지 않은 것

- **검사가 입력과 출력 양쪽에 있다** — 4행이 원문을(`/`로 시작, `//` 아님), 7행이 해석된 origin을, 10행이 **해석된 경로**를 본다.
  10행이 핵심이다: 점 세그먼트 해석이 `/.//host`를 `//host`로 바꾸므로(8-9행 주석) 입력만 보는 검사는 뚫린다.
  테스트가 적대적 HTTP 실행에서 찾은 여덟 형태(`navigation.test.ts:19-30` — `%2e`, `%2E%2E`, 역슬래시 혼합 포함)를 고정한다
- **역슬래시** — `/\host`는 WHATWG 파서가 특수 스킴에서 `\`를 `/`로 읽어 호스트가 바뀌므로 7행 origin 비교가 잡는다.
  `/.\\host`처럼 경로에 남는 경우는 10행 `[/\\]`가 잡는다. 탭·개행은 파서가 제거한 뒤 같은 두 검사를 거친다
- **4행의 `//` 원문 검사는 7행과 겹친다** — `//host`는 origin 비교에서도 떨어진다. 비용 없는 조기 반환이고 의도가 읽히므로
  중복으로 지적하지 않는다
- **`https://snumps.invalid` 기준 URL(1행)** — `.invalid`는 RFC 2606 예약 TLD라 실제 호스트와 겹칠 수 없는 감시값이다.
  배포 도메인과 무관하게 동작하는 것이 맞다. 상수로 이름이 붙어 있다
- **출력이 `pathname + search + hash`로 재조립된다(11행)** — 원문이 아니라 파서가 정규화·인코딩한 값을 돌려주므로 CR/LF 같은
  헤더 주입 문자가 `Location`에 실리지 않는다. `%2F%2Fhost`처럼 인코딩된 슬래시는 디코딩되지 않고 경로로 남는다(안전)
- **`try/catch`가 모든 예외를 `/`로(12-14행)** — 기준 URL이 유효하므로 `new URL`이 던질 입력은 사실상 없고, 던지더라도
  실패 방향이 닫힘(홈)이다. 오류 삼킴이 아니라 fail-closed다
- **반환형이 추론(`string`)** — 15줄짜리 순수 함수에서 명시를 요구하는 것은 과하다
- **호출부는 하나(`(public)/login/+page.server.ts:16`)** — 결과는 서버 `redirect(303)`와 Auth.js `redirectTo`(`login/+page.svelte:13`)
  두 곳에 쓰인다. 둘 다 이 함수를 통과한 값만 받는다
- **이 함수 밖의 관찰(이 파일의 결함 아님)**: `?redirect=`를 **만드는** 쪽이 둘이고(`auth-guards.ts:59`, `guards/zone.ts:141`)
  둘 다 `url.pathname`만 싣는다. 이 함수가 테스트로 보존하는 쿼리스트링(`navigation.test.ts:5-9`)이 생산 단계에서 이미 버려진다 —
  `/settings/notifications?source=mail` 같은 메일 링크로 들어와 로그인하면 `?source`가 사라진다. 두 생산자 리뷰에서 다룰 것
