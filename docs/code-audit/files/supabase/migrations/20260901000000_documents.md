## LA42-1 🟠 `assets` 버킷을 공개로 만든다 — C-22 결정과 반대이고, 재실행으로도 수렴하지 않는다

83행 `('assets', 'assets', true)`, 73-74행 주석 "public serving comes solely from public=true".

C-22는 이 버킷을 **비공개로 돌리기로** 결정했다(`FUNCTIONAL-SPEC.md:228` SYS-04 "비공개 버킷 +
`/media/<key>` 프록시", `PRIORITY.md:447` "결정·처리됨"). 코드는 이미 그 전제로 움직인다 —
`storage.ts:150-170`이 서명 URL을 발급하고, `asset-cleanup.ts:24-26`은 "비공개로 돌린 지금"이라고 쓴다.
그런데 그 결정을 **실행하는 것은 이 마이그레이션이 아니라** 운영 스크립트 하나다
(`OPERATOR-TODO.md:195-213`, `scripts/ops/ops-assets-private.mjs --apply`).

결과:

- 이 파일로 새로 세운 환경(일시정지된 dev를 다시 만들 때, 재해 복구, 새 프로젝트)은 **공개 버킷으로
  태어난다.** 스크립트를 잊으면 `/media` 프록시의 요청별 권한 판정이 통째로 우회된다 — 취소된
  세미나의 포스터·자료가 저장소 공개 URL로 계속 나간다(C-22가 막으려던 바로 그 경로).
- 86행 `on conflict (id) do nothing`이라 재실행은 이미 있는 버킷의 `public`을 고치지 않는다.
  "재실행 안전"(9행)은 참이지만 "재실행하면 선언된 상태가 된다"는 아니다 — 그리고 선언된 상태 자체가 낡았다.

처방: 이 파일은 고치지 않는다는 규칙(`ATOMIC-FLOWS.md:95`)이 있으므로 새 마이그레이션에
`update storage.buckets set public = false where id = 'assets';`(재실행 안전)를 두고, 73-74행 주석이
가리키는 사실을 그 파일이 이어받게 한다. 운영 스크립트는 확인용으로 남긴다.
**동작 변경** — 아직 공개인 환경을 비공개로 만든다(그것이 결정된 동작이다).

## LA42-2 🟡 "추가 전용"이 `TRUNCATE`를 막지 않는다

67-69행은 `before update or delete ... for each row` 트리거다. 행 트리거는 `TRUNCATE`에서 발화하지
않고, RLS(46-48행)도 `TRUNCATE`에는 적용되지 않는다. PGlite에 이 마이그레이션을 올리고 트리거가
켜진 채로 `truncate audit_log`를 실행하면 **성공하고 0행이 남는다**(이번 검토에서 실행해 확인).

51-54행은 이 트리거를 "파기 증거를 secret key로부터도 지킨다"고 설명한다. 🟡인 이유는 도달성이
아니라 **계약의 범위**다: secret key의 경로는 PostgREST이고 PostgREST에는 `TRUNCATE`를 표현할
방법이 없으므로, 적힌 위협에 대해서는 트리거가 계약을 지킨다. 구멍은 SQL 세션을 가진 역할에만
열려 있고, 그중 소유자는 어차피 트리거를 끌 수 있다. 남는 것은 "append-only"라는 이름이 한 문장
종류를 빠뜨린다는 사실이다.

처방: `create trigger audit_log_no_truncate before truncate on audit_log for each statement execute
function audit_log_immutable();`를 새 마이그레이션에 추가. 함수는 `tg_op`를 이미 메시지에 싣는다.
테스트 초기화(`store-memory.ts:181-192`)는 트리거를 끄고 `delete`하므로 영향이 없다. **구조만 바뀐다.**

## 확인했고 지적하지 않은 것

- **정책 0개의 RLS**(38-48행) — 의도적인 deny-all이고 주석이 이유(서버만 secret key로 접근, secret
  key는 RLS 우회)와 "정책을 추가하지 말 것"을 명시한다. `FORCE ROW LEVEL SECURITY`가 없는 것도
  같은 설계다 — 서버 역할은 어차피 BYPASSRLS다
- **`anon`/`authenticated`의 표 권한을 회수하지 않는다** — 행 접근은 RLS가 막고, 함수 실행 권한은
  `20260928000000_atomic_flows.sql:1157-1174`가 회수한다. LA42-2의 `TRUNCATE`만 예외이고 거기서 다뤘다
- **`version bigint not null default 1`** — TS 생성 경로도 `version: 1`로 넣는다(`store.ts:84`).
  흐름의 `app_lock`(`atomic_flows.sql:42-45`)도 같다. 세 곳이 같은 값이다
- **`create table if not exists`는 열 변경을 수렴시키지 않는다** — 표 모양 변경은 새 마이그레이션으로
  한다는 규칙(`ATOMIC-FLOWS.md:95,103`)이 있고, 문서 모양은 JSONB 안이라 이 파일이 관여하지 않는다
- **`audit_log.at default now()`** — TS(`audit.ts:102-110`)와 흐름(`app_audit`)이 항상 값을 넣으므로
  기본값은 쓰이지 않지만, 열 정의로서 해가 없다
- **`audit_log_immutable()`이 권한 회수 루프(`atomic_flows.sql:1166`의 `app\_%`/`flow\_%`) 밖이다** —
  트리거 함수는 직접 호출하면 오류가 나므로 `EXECUTE` 권한이 남아도 쓸 길이 없다
- **Storage 정책 없음**(77-78행) — 표와 같은 근거의 의도적 선택
- **PGlite에서도 실행된다** — `pglite-bootstrap.ts:9-13`이 `storage.buckets` 대역을 먼저 만든다
