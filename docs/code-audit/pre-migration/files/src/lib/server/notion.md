## ~~SH-2~~ **철회** — 주석은 틀리지 않았다

초판은 `"Backward compatibility layer"`가 "구 소비자가 따로 있다"는 뜻으로 읽히므로
거짓이라고 했다. **반대다.** 호환 셰임은 구 **소비자**가 아니라 구 **경로**를 보존한다.
`$lib/server/notion`이 바로 그 분할 이전 경로이고, 16곳이 여전히 그걸 쓰는 이유가 그것이다.
**주석은 역사적으로 정확하다.**

근거로 든 것도 지어낸 인과였다 — _"그래서 `MemberRepository.ts:2`가 `../notion/schema`를
직접 가리킨다"_. `schema.ts`는 **배럴에 아예 없어서**(`index.md` IX-2) 직접 import 외에
방법이 없다. 주석 문구와 무관하다.

그리고 초판 스스로 우선순위에 "N-1을 하면 사라진다"고 적었다 —
**지우자고 권한 파일의 주석을 고치자고 18줄을 썼다.**

## 지적하지 않은 것

- **`./notion/index`로 `/index`를 명시한 것**: `./notion`으로 쓰면 **자기 자신으로 해석된다**
  (상대 경로가 `src/lib/server/`를 기준으로 풀리고 파일이 디렉터리를 이긴다).
  검증에서 실제로 시도한 결과 오류 40 → **80**, `TS2305` 52건.
  **`/index` 명시가 맞다** — 이 파일에서 유일하게 비자명하게 옳은 지점이다
- **`export *` 사용**: 셰임의 목적이 "전부 그대로 전달"이므로 적절
- **`$lib/server` 보호**: 삭제해도 경계가 바뀌지 않는다. 두 파일 다 `src/lib/server/**` 아래다
- **부수효과 그래프**: 삭제해도 `cache.ts`의 `new Redis(...)`는 그대로다.
  셰임은 `index.ts` **위**의 순수 통과 계층이라 그 경로에 없다 —
  청크가 2003 B로 바이트 동일한 것이 그 증거다 (`index.md` IX-6과 혼동하지 말 것)
