> 기준일: 2026-09-10 (2차 검증) · `main` `76a5cda` 대비 26커밋

## 1. URL 표면 — 기계적 비교

`main`과 `HEAD`를 각각 `DATA_BACKEND=memory`로 빌드하고 `.vercel/output/config.json`의
라우트 표를 비교했다. 라우트 62 → 57.

### 사라진 URL — 5개, 결정에 따라 삭제된 것

```
/experiment/1  /experiment/2  /experiment/3  /experiment/4  /experiment/index
```

**`SCOPE.md` C-1(2026-08-23) 결정의 실행 결과다.** 이 브랜치 첫 커밋 `292770a`에서 처리했다.
비교 결과에 나타나는 것은 삭제가 의도대로 반영됐다는 확인이지 재검토 대상이 아니다.

### 서빙 방식만 바뀐 URL — 9개, 주소는 그대로

```
/about  /about/charter  /about/elections  /about/finance  /about/press
/archive/problems  /archive/discussions  /archive/misc  /archive/misc/integration-bee
```

정적 파일 → 함수 리라이트. **URL도 내용도 같다.** 비교 결과에서 이 아홉이
"사라진 것"과 "새로 생긴 것" 양쪽에 나타나는 이유가 그것이다 —
앞쪽은 정적 파일용 후행 슬래시 정규화 항목이고 뒤쪽은 함수 리라이트다.

정적 산출물에서는 HTML 9개와 `__data.json` 9개가 사라졌다. 이것이 C-17의 목적이었다 —
그 `__data.json`에 회원 이름·학과·프로젝트 URL이 구워져 있었고 캐시 실드 밖이었다.

- **환경변수 요구**: `.env.example` 무변화. 새 변수 없음

`--frozen-lockfile`이 실패해 **원래 동작하지 않았다**.

## 3. 회귀 — 확인하고 닫았다 (`070ac97`)

`/archive/problems` · `/archive/discussions` · `/archive/misc` · `/archive/misc/integration-bee`

정적 파일이던 네 공지 페이지가 함수 렌더가 되면서, 스냅샷을 화면에 쓰지도 않으면서
아카이브 레이아웃의 테이블 7개 읽기에 의존하게 됐다. 그 `Promise.all`에 try/catch가 없었다.

### 실측 — 논증이 아니라 재현

`SUPABASE_URL` 없이 dev 서버를 띄우고 수정 전 커밋(`191d2ce`)과 수정 후를 같은 조건으로 요청했다.

|                                      | 수정 전                                          | 수정 후                                 |
| ------------------------------------ | ------------------------------------------------ | --------------------------------------- |
| 서버 로그                            | `[500] GET /archive/problems`                    | `[archive] snapshot unavailable` (삼킴) |
| `<title>`                            | `서울대학교 수학문제연구회 SNUMPS` (오류 페이지) | `문제 창작 자료 · SNUMPS`               |
| 페이지 고유 콘텐츠(`문제 창작`) 출현 | **0회**                                          | 2회                                     |
| 본문의 `error` 문자열                | 29회                                             | —                                       |

> dev 서버는 오류 페이지도 HTTP 200으로 내보낸다. **상태 코드만으로는 판별할 수 없어**
> 서버 로그와 본문 콘텐츠로 판정했다.

### 고친 방식 — 지적 하나를 함께 닫는다

`Promise.all`을 try로 감싸고 실패 시 빈 스냅샷 + `dataAvailable: false`를 반환한다.
그 필드는 **원래 이 상태를 표현하려고 있던 것**인데 생산자가 없어 소비자 다섯 곳의
else 분기가 죽은 코드였다(`ZR-1`). 생산자를 만들면서 셋이 동시에 해결됐다 —
네 공지 페이지의 가용성, 갤러리·프로젝트의 500 대신 안내 렌더, 그리고 `ZR-1`.

테스트 3개로 고정했다: 모든 읽기가 실패해도 던지지 않고 반환한다, 빈 스냅샷이 다섯 키를
전부 빈 배열로 갖는다(소비자가 가드 없이 구조분해한다), `generatedAt`은 여전히 찍힌다.

## 4-2. 2차 검증 — 실행 비교 (2026-09-10)

1차는 라우팅 표 비교가 중심이었다. 그 뒤 8커밋에서 **lint 수정이 런타임 코드를 건드렸으므로**
(`$state`+`$effect` → `$derived`, `{#each}` 인덱스 키, 정규식 이스케이프) 양쪽을 **실제로 띄워
비교**했다.

방법: `main`과 `HEAD`를 각각 `DATA_BACKEND=memory` + **동일한 `.env`** 로 dev 서버에 올리고,
공개 21 + 관리자 10(`?dev_preview=admin`) + 회원 4(`?dev_preview=member`) = **35개 라우트**를 훑었다.

| 항목             | 결과                                                                     |
| ---------------- | ------------------------------------------------------------------------ |
| URL 표면         | 62 → 57. 사라진 것은 실험 라우트 5개뿐(C-1 결정). **새로 생긴 URL 없음** |
| 상태 코드        | **35개 전부 동일**, 전부 200                                             |
| `<title>`        | **35개 전부 동일**                                                       |
| 서버 측 500 처리 | 양쪽 **0건** (dev는 오류 페이지도 200을 내므로 서버 로그로 판정)         |

| 라우트                         | 차이                                                                   |
| ------------------------------ | ---------------------------------------------------------------------- |

### 관리자 큐 API

```
main: {"applications":[],"success":true,"items":[],"generatedAt":"…"}
head: {"success":true,"items":[],"generatedAt":"…"}
```

죽은 키 3개만 정확히 빠졌다. `items` 생산 코드는 diff상 손대지 않았다.

### `$derived` + `bind:value` — 컴파일러로 증명

SSR 비교로는 클라이언트 상호작용을 증명할 수 없다. 브라우저가 없어 컴파일러에 물었다:

```
우리 형태  let x = $derived(src)  + bind  → 컴파일 OK, 경고 없음
대조군    const x = $derived(src) + bind  → 컴파일 실패 constant_binding
대조군    const x = 1             + bind  → 컴파일 실패 constant_binding
                                            (svelte 5.56.10)
```

**컴파일러가 이 부류를 실제로 거부한다.** 따라서 빌드 통과가 공허한 증거가 아니라,
쓰기 가능한 derived 바인딩으로 승인됐다는 뜻이다.

### 등가성이 별도로 증명된 것

- `stripInvisibles` 정규식 이스케이프 — **변경 전에 작성한 13건**이 변경 후에도 통과
- `TABLE_NAMES` 런타임 가드 — 가드 로직만 떼어 실행(정상 10 / 누락 / undefined / 낯선 키)
- 아카이브 레이아웃 try/catch — 데이터 계층이 살아 있을 때 페이로드가 타임스탬프 외 동일
