> 기준일: 2026-09-10 · `main` `76a5cda` 대비 15커밋 · 소스 38파일 (+709 / −1,313)

다만 **아카이브 공지 4페이지에 가용성 회귀가 하나 있다** — 배포 전에 닫는 것을 권한다(§3).

## 1. URL 표면 — 기계적 비교

`main`과 `HEAD`를 각각 `DATA_BACKEND=memory`로 빌드하고 `.vercel/output/config.json`의
라우트 표를 비교했다. 라우트 62 → 57.

### 사라진 URL — 5개, 전부 의도된 것

```
/experiment/1  /experiment/2  /experiment/3  /experiment/4  /experiment/index
```

C-1 결정으로 삭제했다. 앱 내 링크가 하나도 없어 URL을 직접 쳐야만 도달했고,
`ExperimentReplica.svelte` 812줄이 여기에만 쓰였다.
**외부에 이 URL을 공유한 적이 있다면 그때만 손실이다.**

### 서빙 방식만 바뀐 URL — 9개, 주소는 그대로

```
/about  /about/charter  /about/elections  /about/finance  /about/press
/archive/problems  /archive/discussions  /archive/misc  /archive/misc/integration-bee
```

정적 파일 → 함수 리라이트. **URL도 내용도 같다.** 비교 결과에서 이 아홉이
"사라진 것"과 "새로 생긴 것" 양쪽에 나타나는 이유가 그것이다 —
앞쪽은 정적 파일용 후행 슬래시 정규화 항목이고 뒤쪽은 함수 리라이트다.

정적 산출물에서는 HTML 9개와 `__data.json` 9개가 사라졌다. 이것이 C-17의 목적이었다 —
그 `__data.json`에 회원 이름·학과·프로젝트 URL이 구워져 있었고 캐시 실드 밖이었다.

### 새로 생긴 URL

### 바뀌지 않은 것 — 확인함

- **환경변수 요구**: `.env.example` 무변화. 새 변수 없음
- **의존성**: `package.json` 무변화
- **인증·권한 규칙**: 존 가드(`zone.ts`)·`resolve-member.ts` 무변화. 관리자 판정 무변화
- **데이터 스키마·마이그레이션**: 무변화
- **`vercel.json`**: 무변화 (크론 스케줄 그대로)

### 삭제했지만 배포에 무관한 것

`Dockerfile` · `docker-compose.yml` · `.dockerignore` — 배포는 `adapter-vercel`이고,
Dockerfile은 adapter-node 산출물(`node build`)을 기대하는 데다 `pnpm-lock.yaml`이 gitignore라
`--frozen-lockfile`이 실패해 **원래 동작하지 않았다**.

## 3. 유일한 회귀 — 아카이브 공지 4페이지의 가용성

`/archive/problems` · `/archive/discussions` · `/archive/misc` · `/archive/misc/integration-bee`

**지금(배포 중)**: 정적 HTML. 데이터 계층이 죽어도 서빙된다.
**이 브랜치**: 함수 렌더. 요청마다 `(public)/archive/+layout.server.ts`를 실행한다.

그 레이아웃은 테이블 7개를 `await Promise.all([...])`로 읽는데 **try/catch가 없다**(`:51-60`).
따라서 데이터 계층이 불가할 때 **500이 난다** — 그 네 페이지는 스냅샷을 화면에 쓰지도 않는데.

**근거는 실측이다.** 프리렌더 제거 전 크레덴셜 없이 빌드하면 정확히 그 네 경로가
`500 … SUPABASE_URL is not set`으로 죽었다. 같은 로드가 이제 요청 시점에 돈다 —
실패가 빌드 타임에서 런타임으로 옮겨간 것이다.

> 갤러리·프로젝트 등 나머지 아카이브 페이지는 **원래도** 프리렌더가 아니어서 같은 의존을
> 갖고 있었다. 회귀는 이 네 페이지에 한정된다.

### 닫는 방법 — 한 곳 수정으로 지적 하나까지 함께 해소

`Promise.all`을 try로 감싸고 실패 시 빈 스냅샷 + `dataAvailable: false`를 반환한다.

이것이 `ZR-1`이 지적한 바로 그 구멍이다 — `dataAvailable`은 **소비자가 5곳 있는데
생산자가 없어서** 그 else 분기가 죽은 코드였다. 생산자를 만들면:

- 네 공지 페이지가 데이터 계층과 무관하게 살아난다
- 갤러리·프로젝트가 500 대신 "데이터 이관 후 …" 안내를 렌더한다
- `ZR-1`이 닫힌다

**권장: 배포 전에 처리.** 범위는 파일 하나, 지적 하나.
